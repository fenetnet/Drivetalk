# Handoff — איפה אנחנו עומדים

_עודכן: 2026-10-02_

## מצב נוכחי

**Phase 1 — prototype מקומי עם נתונים מדומים: בנוי, ממתין לבדיקה של הבעלים.**

מה יש:
- אפליקציית Flutter בעברית מלאה ו-RTL, עיצוב חם ורגוע (גופן Rubik).
- כל המסכים: onboarding, בית, בחירת מצב, בחירת זמן, חיפוש, הצעה עם הסבר, המתנה לאישור,
  מצב נהג, שיחה מדומה, feedback, הזמנה נכנסת, קשרים (4 לשוניות + כרטיס אדם + הוספת חבר),
  גילוי, הגדרות (כולל פרטיות וחסומים), כלי מפתחים + "מנוע ההתאמה — מאחורי הקלעים".
- מנוע התאמה אמיתי (סינון → ניקוד → 10% הפתעה → הסבר), משקלים ב-`assets/config/matching.json`.
- 15 אנשים מדומים מסוגים שונים.
- 26 בדיקות אוטומטיות עוברות; ניתוח קוד נקי.
- GitHub Actions בונה APK בכל עדכון.

מה **אין** בכוונה: שרת, הרשמה, שיחות אמיתיות, זיהוי נסיעה אמיתי, התראות אמיתיות, תמונות.

## איך בודקים

1. **בדפדפן** (הכי מהיר) — קישור לגרסת דפדפן נשלח בשיחה (אם פורסם).
2. **בטלפון Android** — מורידים את `drivetalk-prototype-apk` מ-GitHub → Actions → הריצה האחרונה → Artifacts.
   (מדריך צעד-צעד נשלח בשיחה.)

### תרחישים מומלצים
1. onboarding → "אני פנוי עכשיו" → הליכה → 30 דק׳ → הצעה (דנה) → "לדבר עכשיו" → שיחה מדומה → סיום → feedback.
2. כלי מפתחים → "נכנסתי לרכב" (זמינות אוטומטית כבויה) → מצב נהג בלבד. הגדרות → להפעיל זמינות אוטומטית → שוב "נכנסתי לרכב" → זמין אוטומטית, בלי שיחה אוטומטית.
3. בשיחה במצב נהג → סיום → אין שאלת feedback → "יצאתי מהרכב" → עכשיו נשאלת.
4. כלי מפתחים → "כולם לא זמינים" → להיות זמין → אחרי כמה שניות: "שלחנו הודעה ל-3 אנשים".
5. כלי מפתחים → "דמה הזמנה נכנסת" → "להשתיק" → לנסות שוב → לא נמסרת.
6. כלי מפתחים → "30 יום קדימה" → לראות איך "לחדש קשר" מתמלא.
7. גילוי → להפעיל "חברים של חברים" → בקשרים מופיעה תמר (3 חברים משותפים); מאיה לא מופיעה (לא הסכימה).
8. "מנוע ההתאמה — מאחורי הקלעים" → לראות ציונים וסיבות סינון (למשל Daniel: אין שפה משותפת).

## מה הבא

1. הבעלים בודק ונותן הערות על התחושה, הטקסטים והזרימה.
2. תיקונים לפי ההערות.
3. מיזוג ל-main באישור.
4. Phase 2 (הרשמה + משתמשים + רשת קשרים + Supabase) — **קודם הסבר על חשבון, עלויות וחלופות, ואישור.**
