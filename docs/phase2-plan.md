# Phase 2 — בדיקה אמיתית עם חבר (תוכנית, ממתינה לאישור)

## 1. מה כבר קיים ואפשר להשתמש בו
- **כל המסכים:** בית, בחירת זמן, אפשרויות, המתנה, שיחה (הדמיה), feedback, קשרים, הגדרות.
- **מנוע ההתאמה:** עובד על כל רשימת אנשים, מדומים או אמיתיים.
- **השכבות:** המסכים מדברים רק עם "שירותים". את השירותים המדומים מחליפים בשירותים אמיתיים במקום אחד (`lib/app/providers.dart`), בלי לבנות מסכים מחדש.
- **פרופיל:** שם, תמונה וטלפון כבר נשמרים בטלפון.
- **בדיקות:** 48 בדיקות אוטומטיות, ומסך מפתחים עם תרחישי תקלה.

## 2. מה צריך להוסיף
- **שירותים אמיתיים מול Supabase:** פרופיל, קשרים, זמינות, הצעות והזמנות.
- **שני מצבים נפרדים:** "מצב הדגמה" (האנשים המדומים, כמו היום) ו"בדיקה אמיתית" (משתמשים אמיתיים). הם לא מתערבבים.
- **"הזמן חבר":** יוצר קישור ייחודי ופותח את מסך השיתוף של הטלפון.
- **מסך "הוזמנת":** פותח את הקישור, מראה מי הזמין, ומאשר את ההצטרפות.
- **הצעה הדדית:** כששני קשרים פנויים, שניהם מקבלים הצעה. רק אם שניהם אישרו נוצר Match ונפתח מסך השיחה.
- **מסך "בדיקה עם חבר":** מצב החשבון, החיבור לשרת, החבר, הזמינות, ההזמנה וה-Match, וכפתור "העתק מידע לבדיקה".
- **הגדרות ‹ מצב בדיקה:** מפעיל ומכבה מידע נוסף לבדיקה.
- **חתימה קבועה לאפליקציה:** כך שאפשר להתקין עדכון מעל גרסה קיימת.
- **דף הזמנה באינטרנט:** למי שעוד לא התקין, עם הסבר וכפתור הורדה.

## 3. Backend
**Supabase**, החשבון החינמי:
- **Postgres:** מסד הנתונים.
- **Auth:** התחברות.
- **Realtime:** עדכונים חיים בין הטלפונים.
- **Row Level Security:** הרשאות שנאכפות בשרת עצמו, לא רק באפליקציה.
- **pg_cron:** ניקוי אוטומטי של זמינות שפגה.

**מבנה הנתונים:**
- `profiles`: שם ותמונה.
- `connections`: מי מחובר למי.
- `invitations`: הזמנות. הקוד אקראי באורך 128 ביט, חד-פעמי, ובתוקף 7 ימים.
- `availability`: מצב, התחלה וסיום.
- `match_offers`: הצעה, האישור של כל צד, וסטטוס.

**כללי הגישה:**
- פעולות רגישות עוברות דרך פונקציות בשרת: קבלת הזמנה, אישור או דחייה של הצעה.
- כל משתמש רואה רק את עצמו ואת הקשרים שלו.
- אימייל ומספר טלפון לא נחשפים לאף אחד.

## 4. התחברות — המלצה
**לגרסת הבדיקה: כניסה עם שם בלבד** (במונחי Supabase: Anonymous sign-in).
- **למה:** אפס חיכוך. לא צריך אימייל, לא צריך SMS, לא צריך להגדיר שירות נוסף.
- **החיסרון:** מי שמוחק את האפליקציה מאבד את החשבון וצריך הזמנה חדשה. בבדיקה של שניים זה בסדר.
- **מה הלאה:** קוד באימייל (OTP), כשיהיו יותר בודקים. אותו קוד יעבוד גם ב-iPhone.
- **למה לא עכשיו:**
  - SMS עולה כסף.
  - כניסה עם Google דורשת הגדרות ב-Google Cloud.
  - קישור קסם (Magic link) מסבך את הקישורים לאפליקציה.

## 5. ההזמנה לחבר
- **הקישור:** `https://<דף ההזמנה שלנו>/i/<קוד>`.
- **אם האפליקציה מותקנת:** Android App Links פותח את מסך ההזמנה ישר באפליקציה. אותו קישור יעבוד בעתיד גם ב-iPhone (Universal Links).
- **אם היא לא מותקנת:** נפתח דף פשוט: "נתנאל מזמין אותך" ‹ 1. הורד ‹ 2. התקן ‹ 3. "פתח את ההזמנה".
- **גיבוי:** הקוד מופיע גם כטקסט, ואפשר להדביק אותו באפליקציה ב"יש לי קוד הזמנה".
- **אחסון הדף:** חינמי. צריך לבחור:
  - **GitHub Pages:** חינם רק אם הפרויקט ציבורי. אין בו סודות, אבל הקוד יהיה גלוי.
  - **Cloudflare Pages:** חשבון חינמי, והפרויקט נשאר פרטי.

## 7. זמן אמת בין שני הטלפונים
- **Supabase Realtime:** כל שינוי בזמינות או בהצעה מגיע לטלפון השני תוך שנייה או שתיים, כששתי האפליקציות פתוחות.
- **סוף זמינות:** לכל זמינות יש `expires_at`. השרת מתעלם ממה שפג, וכל דקה הוא גם מנקה זמינות שפגה. גם אם האפליקציה נסגרה, אף אחד לא נשאר "פנוי".
- **אישור הדדי:** פונקציה בשרת מסמנת "אושר" רק כששני הצדדים אישרו. היא מטפלת גם בלחיצה באותה שנייה.
- **אחרי דחייה:** הצד השני רואה "לא הסתדר הפעם".

## 8. מה הבעלים צריך לעשות (אדריך צעד-צעד)
1. **חשבון Supabase חינמי ופרויקט:** ולהעתיק אליי שני ערכים, Project URL ו-anon / publishable key. שני הערכים האלה ציבוריים בכוונה, ומותר שיהיו באפליקציה.
   **אסור** לשלוח או לשמור את ה-service_role key או את סיסמת מסד הנתונים.
2. **שני "סודות" ב-GitHub:** בהגדרות הפרויקט, למפתח החתימה של האפליקציה.
3. **בחירת אחסון לדף ההזמנה:** GitHub Pages (הפרויקט נהיה ציבורי) או Cloudflare Pages (חשבון חינמי).

## 9. מה בחינם
- **Supabase:** Auth, Realtime, מסד נתונים של 500MB ו-50,000 משתמשים בחודש.
- **GitHub Actions:** בניית האפליקציה.
- **אחסון דף ההזמנה.**
- **קובץ ההתקנה.**

Push (התראות) דרך Firebase Cloud Messaging גם הוא חינמי, אבל דורש פרויקט Firebase והגדרות. **מומלץ לדחות לשלב הבא.**

## 10. מגבלות צפויות
- **השהיית Supabase:** פרויקט חינמי נעצר אחרי 7 ימים בלי שימוש. מפעילים אותו מחדש בלחיצה.
- **בלי Push:** החבר יראה "נתנאל פנוי" רק כשהאפליקציה פתוחה אצלו.
- **אזהרות התקנה:** Play Protect ו"מקור לא ידוע" ימשיכו להופיע עד שנעבור ל-Google Play.
- **מחיקת האפליקציה:** בכניסה עם שם בלבד, מחיקה פירושה משתמש חדש.
- **החלפת חתימה:** מעבר לחתימה קבועה יחייב **פעם אחת** להסיר את הגרסה הקיימת ולהתקין מחדש.
- **השיחה:** עדיין הדמיה. שיחת קול אמיתית בתוך האפליקציה תהיה ב-Phase 5, והיא דורשת אישור.
- **iPhone:** עדיין לא. הכל נבנה כך שיתאים גם לו בהמשך.
